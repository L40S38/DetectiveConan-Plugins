# 名探偵コナン 調査・考察

プラグインに同梱したデータ（伏線リスト・考察項目・人物索引・知識表・編纂室データベース）を土台に、足りない分を Web で補って答える。このスキルではデータを書き換えない。

## データの場所

| 内容 | パス |
|---|---|
| 記法の約束事（最初に読む） | `${CLAUDE_PLUGIN_ROOT}/data/conventions.md` |
| 参考サイトと信頼度 | `${CLAUDE_PLUGIN_ROOT}/data/sources.md` |
| 人物索引（別名の逆引き・人物カード・劇場版への登場） | `${CLAUDE_PLUGIN_ROOT}/data/characters.md` |
| 伏線リスト（一覧＋分類別） | `${CLAUDE_PLUGIN_ROOT}/data/foreshadowing/` |
| 考察項目リスト | `${CLAUDE_PLUGIN_ROOT}/data/open-questions.md` |
| 知識表（誰が何を知っているか、テーマ別） | `${CLAUDE_PLUGIN_ROOT}/data/knowledge-matrix/` |
| 編纂室データの検索ツール | `${CLAUDE_PLUGIN_ROOT}/scripts/conan_db.py` |
| 編纂室データ（CSV、submodule） | `${CLAUDE_PLUGIN_ROOT}/database/dataset_csv/` |

## Step 0: ネタバレの範囲を決める

- ユーザーが既読範囲を示したら（例：「100巻まで」「アニメ勢」「劇場版は黒鉄の魚影まで」）、それより後の情報は答えに入れない。
  - 伏線は、既読範囲より後に回収された項目についてタイトルと状態だけを見せ、「回収」欄の中身は伏せる。
  - 知識表・人物カードは答えを含む。既読範囲より後の話数を根拠にしたセルや記述は、その旨だけ伝えて中身を伏せる。
- 既読範囲の指定がなければ、最新の情報時点まで含めて答え、冒頭にその旨を 1 行で書く（Step 4）。
- 質問の文面から未読らしいとわかる場合（「アニメで追っているんだけど」など）は、範囲を確認してから答える。

## Step 1: 質問の種類を見分ける

| 種類 | 例 | まず読むもの |
|---|---|---|
| 事実確認 | 「ピスコの本名は？」 | `characters.md` |
| 伏線を追う | 「ラムの伏線を時系列で」 | `foreshadowing/README.md` → 分類別ファイル（ID で関連をたどる） |
| 考察 | 「ボスは生きていると思う？」 | `open-questions.md` → 関連する伏線 |
| 知識状態 | 「赤井の生存を知っているのは誰？」 | `knowledge-matrix/` の該当する表 |
| 話数・巻・初登場 | 「File 1103 は何巻？」「若狭先生の初登場は？」 | `conan_db.py` |
| 劇場版 | 「緋色の弾丸に出た赤井家は？」 | `characters.md` の「(c) 劇場版への登場」、伏線の MOVIE 分類 |

## Step 2: データを読む

1. `conventions.md` を読み、情報時点・正史区分タグ・記号の意味を確かめる。
2. 人物名は `characters.md` の「(a) 別名 → 人物 ID の逆引き」で ID にそろえる（例：沖矢昴 → `C-akai-shuichi`）。
3. 知識状態の質問は、テーマに合う表だけを読む。

   | テーマ | ファイル |
   |---|---|
   | コナン＝新一 | `01-conan-shinichi.md` |
   | 灰原＝志保・APTX | `02-haibara-aptx.md` |
   | 赤井家 | `03-akai-family.md` |
   | 羽田浩司事件 | `04-haneda-case.md` |
   | 組織の正体・潜入 | `05-black-org.md` |
   | 警察・公安 | `06-police.md` |
   | キッド・黒羽盗一 | `07-kid.md` |

   接近度（段階値）の意味は `knowledge-matrix/README.md` にある。`?` は「描写がない、またはまだ確かめていない」なので、`?` のセルは Web で補えるか確かめてから答える。
4. 話数・巻・初登場は、CSV を直接読まずに `conan_db.py` で引く。CSV の `number` 列は公式の File 番号とずれている（欠け・重複があるため）。

   ```
   python "${CLAUDE_PLUGIN_ROOT}/scripts/conan_db.py" file 1103
   python "${CLAUDE_PLUGIN_ROOT}/scripts/conan_db.py" case 17年前
   python "${CLAUDE_PLUGIN_ROOT}/scripts/conan_db.py" char 若狭留美
   python "${CLAUDE_PLUGIN_ROOT}/scripts/conan_db.py" vol 108
   python "${CLAUDE_PLUGIN_ROOT}/scripts/conan_db.py" latest
   ```

   事件のあらすじは `database/dataset_csv/Number-Title-Explain.csv` を事件名で Grep する（編纂室の公式あらすじなので、Web の要約より信頼できる）。
   database が無いときは「submodule が取得されていない」と伝え、名探偵コナン編纂室 https://websunday.net/conandb/ を直接見る。

## Step 3: 足りない分を Web で補う

- `sources.md` の信頼度の順（A 公式 → B 準公式 → C ファン Wiki → D 考察・速報）に当たる。「(c) 用途別の逆引き」で、どこを見るかを決める。
- database に無い新しい話（単行本未収録）の内容は、D の速報系 **2 サイト以上** で一致したものだけを事実として扱う。
- WebFetch の要約は人名や話数を取り違えることがある。話数・人物名は原文か database で確かめる。
- 確かめられなかったことは「要確認」と書き、推測で埋めない。

## Step 4: 答える

- 冒頭の 1 行に、情報の範囲を書く。例：「原作 File 1167・劇場版第 29 作までの情報を含みます（ネタバレあり）」
- 主張ごとに出典と正史区分タグを付ける。例：「ラムの左目は義眼 — 原作 File 1066（100巻）[原作]」
- 事実と推測を分ける。説には `[ファン説]` を付け、作者の発言には `[公式発言]` を付ける。
- 劇場版・アニオリ・スピンオフの描写は原作と混ぜない。使うときは `[劇場版]` などを付け、原作でどうなっているかも添える。

### 出力テンプレート

**知識状態**

```markdown
原作 File 1167 までの情報を含みます。

## 赤井秀一が生きていることを知っている人物（表3 K3-2）
| 人物 | 状態 | 根拠 |
|---|---|---|
| 工藤新一 | ● 確定で知っている | 原作 File 894–898（85巻「緋色シリーズ」）[原作] |
| 世良真純 | △ 疑っている | 要確認 |

- 表の `?`（不明）だった人物：…（Web で補った場合はその出典）
```

**伏線を追う**

```markdown
## ラムの正体をめぐる伏線（F-RUM-001, F-RUM-002）
| 時期 | 出来事 | 出典 |
|---|---|---|
| 86巻 | 黒田兵衛が登場（義眼） | 原作 File 913 [原作] |
| … | … | … |

- 回収：…（既読範囲より後なら伏せる）
- 関連する考察：Q-011
```

**考察**

```markdown
## 問い：赤井務武は生きているのか（Q-013）
### 確定している事実
- …（出典）
### 仮説
- 説A [ファン説]：… ／根拠：… ／反証：…
- 説B [ファン説]：…
### 確からしさの見立て
…
### 今後の注目点
…
```

## Step 5: データの不足や誤りに気づいたら

答えの最後に「データ更新の提案」として、直すべき箇所（ファイル・ID・セル）と根拠を短く挙げる。書き換えはせず、update スキルを使うよう勧める。
