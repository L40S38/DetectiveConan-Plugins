# データ記法の約束事

このプラグインの `data/` 以下のファイルはすべて、この約束事に従って書く。
research スキルはこの約束事を前提に読み、update スキルはこの約束事を守って書き換える。

## 1. 情報時点

データには「どの話までの情報か」を必ず書く。今の情報時点は次のとおり（更新したらここと `knowledge-matrix/README.md` の両方を直す）。

| 媒体 | 情報時点 |
|---|---|
| 原作（週刊少年サンデー） | File 1167「迷い込んだ蘭」（単行本未収録／サンデー 2026 年 42・43 合併号）まで（2026 年 9 月時点） |
| 単行本 | 109 巻まで（2026-10-16 発売） |
| 劇場版 | 第 29 作『ハイウェイの堕天使』（2026-04-10 公開）まで |
| データ更新日 | 2026-10-18 |

## 2. 正史区分タグ

主張や描写には、どの媒体の情報かをタグで示す。

| タグ | 意味 |
|---|---|
| `[原作]` | 青山剛昌『名探偵コナン』の連載・単行本 |
| `[まじっく快斗]` | 青山剛昌『まじっく快斗』の連載・単行本 |
| `[劇場版]` | 劇場版アニメ。原作の正史とは別扱い |
| `[アニオリ]` | TV アニメのオリジナル回 |
| `[TVSP]` | TV スペシャル・OVA など |
| `[スピンオフ]` | 『ゼロの日常』『警察学校編 Wild Police Story』『犯人の犯沢さん』など、青山剛昌以外が描いた派生作品 |
| `[公式発言]` | 作者インタビュー、公式ガイドブック、サンデー誌面のコメントなど |
| `[ファン説]` | ファンの考察・推測。確定情報ではない |

- 劇場版・アニオリ・スピンオフの描写は、原作と食い違っていても「その作品ではこう描かれた」として記録する。原作の事実として書かない。
- アニメの原作回は `[原作]` として扱い、アニメ話数を補足に書く。

## 3. 出典の書き方

```text
アニメ第 1077 話
劇場版第 26 作『黒鉄の魚影』
[公式発言] 2017-12-13 サンデーうぇぶり配信の作者コメント
```

原作の File の書き方は、下の 3.1 に分けて書く。

- **確かめられなかった話数・事実** は、断定せずに「要確認」と書く。推測で埋めない。

### 3.1 原作の File の書き方

File を書くときは、必ず「どの話か」がわかる名前を付ける。書き方は、その File が **database に入っているかどうか** で 2 通りに分かれる。単行本が出ているかどうかではなく、`python scripts/conan_db.py file <番号>` で引けるかどうかで決める。

| | database に入っている話 | database に入っていない話 |
|---|---|---|
| 見分け方 | `conan_db.py file <番号>` で巻・事件名・話タイトルが出る | 「database に無い」と出る（database の最新の話は `conan_db.py latest` で確かめる） |
| 1 話 | `File 番号「話タイトル」（巻「事件名」）` | `File 番号「話タイトル」（単行本未収録／サンデー 年 号）` |
| 範囲 | `File 番号–番号（巻「事件名」）` | `File 番号「話タイトル」〜File 番号「話タイトル」（単行本未収録／サンデー 年 号〜号）` |
| 名前の出典 | database の表記 | D の速報系 2 サイト以上で一致したもの |

#### database に入っている話

```text
原作 File 1047–1050（98・99巻「天罰くだる誕生パーティー」）
原作 File 1049「とても信じられない・・・」（99巻「天罰くだる誕生パーティー」）
原作 File 1150「混沌の追跡者たち」（108巻「混沌の行先」）／サンデー 2025 年 36・37 合併号
原作 File 891–893（84巻「緋色シリーズ［序章／追求］」）・File 894–898（85巻「緋色シリーズ［交錯／帰還／真相］」）
原作 File 585–586（56巻「赤と黒のクラッシュ［発端／血縁］」）〜File 605–609（58・59巻「赤と黒のクラッシュ［嫌疑／潔白／決死／殉職］」）
```

- 1 話だけを指すときは、File 番号の直後に話タイトルも付ける。複数の話の範囲なら事件名だけを書く。
- 事件名と話タイトルは、database の表記をそのまま使う（［…］の副題も含める）。ただし、半角の [ ] は全角の［］に、名前の中の「」は『』に直す。database の事件名は空白が抜けていたり全角英数字だったりするが、そのまま使う（database と突き合わせられるようにするため）。
- 単行本の発売前でも、database に入っていればこの形で書く（例：110 巻の File 1165–1166）。
- 範囲が database の複数の事件にまたがるときは、事件ごとに分けて「・」でつなぐ。3 つ以上に分かれるとき（間に別の事件をはさむシリーズなど）は、最初と最後の事件だけを「〜」でつなぐ。
- 1 つの話が database で 2 つの事件に重なって載っているとき（`conan_db.py anomalies` に出る）は、引いている場面が属する事件を書く。

#### database に入っていない話

```text
原作 File 1167「迷い込んだ蘭」（単行本未収録／サンデー 2026 年 42・43 合併号）
```

- database の最新より後の話（単行本未収録）は、事件名がまだ無いので、巻と事件名の代わりに `（単行本未収録／サンデーの掲載号）` を書く。
- 話タイトルは 1 話でも範囲でも書く。範囲なら最初と最後の話を「〜」でつなぐ。
- 話タイトルと掲載号は、D の速報系 2 サイト以上で一致したものだけを書く。確かめられなければ「要確認」と書く。
- 単行本が出ているのに database に無いときは、この形で書かずに、先に database を更新する（`skills/update/SKILL.md` の Step 1）。
- database を更新して引けるようになった話は、「database に入っている話」の形に直す。

#### どちらにも共通

- 同じ文の中で同じ File をもう一度指すときも省略しない。省略したいときは「上記の回」のように書き、File 番号を出さない。
- File 番号は `conan_db.py` で引いた値を使う。database の CSV の `number` 列は公式の File 番号とずれることがあるので、そのまま使わない。
- database は名探偵コナン編纂室の「事件」単位のデータ。人物の初登場を `conan_db.py char <名前>` で引くと、**その人物が出た事件の最初の File** になる（事件の途中の話で初めて出た場合でも、事件の先頭 File が出る）。回想のみの登場も含まれる。
- `lint_data.py` は、この形になっていない File 表記を警告する。見るのは形だけで、名前が database と合っているかは見ない。

## 4. ID 規則

| 種類 | 形式 | 例 |
|---|---|---|
| 伏線 | `F-<分類>-NNN` | `F-RUM-002` |
| 考察 | `Q-NNN` | `Q-011` |
| 知識表の列 | `K<表番号>-<列番号>` | `K5-3` |
| 人物の掘り下げの列 | `P<表番号>-<列番号>` | `P1-4` |
| 人物 | `C-<ローマ字>` | `C-akai-shuichi` |

伏線の分類。詳細は `foreshadowing/` 以下、分類ごとのファイルに分かれている（一覧は `foreshadowing/README.md`）：

| 分類 | 範囲 | ファイル |
|---|---|---|
| `ORG` | 黒ずくめの組織 | `foreshadowing/01-org.md` |
| `RUM` | ラム・羽田浩司事件 | `foreshadowing/02-rum.md` |
| `AKAI` | 赤井家 | `foreshadowing/03-akai.md` |
| `KUDO` | 工藤家・コナン | `foreshadowing/04-kudo.md` |
| `APTX` | 薬・宮野家 | `foreshadowing/05-aptx.md` |
| `POL` | 警察・公安 | `foreshadowing/06-pol.md` |
| `KID` | 怪盗キッド・黒羽盗一 | `foreshadowing/07-kid.md` |
| `REL` | 人間関係（正体の秘密・カップルの行方・グループの変化を含む） | `foreshadowing/08-rel.md` |

- ID は一度振ったら変えない。項目を消すときも ID は再利用しない。
- 人物 ID の振り方：
  - 日本人名はヘボン式ローマ字で姓-名の順（例：`C-miyano-shiho`）。外国人名は日本語表記の順（例：`C-jodie-starling`）。
  - 本名で振る。組織に潜入している捜査官も本名（例：バーボンは `C-furuya-rei`）。
  - 組織の構成員（潜入捜査官を除く）はコードネームで振る。本名が判明していても変えない（例：`C-gin`、`C-vermouth`、`C-rum`）。
  - 本名がはっきりしない人物は、作中で今いちばん使われている名前で振る（例：`C-wakasa-rumi`）。
  - 複数人をまとめたカードは内容がわかる名前にする。

## 5. タイトルの書き方（伏線・考察）

- タイトルは **謎の形** で書く（「〜は誰か」「なぜ〜か」「〜は本当か」）。
- **答えや回収結果をタイトルに入れない。** 答えは伏線の「回収」欄にだけ書く。
- **ほかの謎の答えになる名前・事実もタイトルに使わない。**
  - 例：「メアリー」ではなく「領域外の妹」、「降谷零」ではなく「安室透」、「脇田兼則」ではなく「ラム」
- こうしておくと、一覧表（ID・タイトル・状態）だけならネタバレなしで読める。

## 6. 知識表の記号

どの列も、次の記号のどれかで書く。

| 記号 | 意味 |
|---|---|
| `◎` | 確定で知っている |
| `〇` | 推理でたどり着いているが、確証の描写がない（または一部だけ知っている） |
| `△` | 疑っている・違和感を持っている |
| `✕` | 知らない |
| `ー` | 本人である・該当しない |
| `?` | そのテーマに関わる場面はあるが、知っているかが描かれていない（または確かめきれていない） |

- 根拠が正史外（劇場版・アニオリ・スピンオフ）の描写だけのときは `†` を付ける（例：`◎†`）。
- そのテーマに関わる場面が無い人物は、`?` ではなく `✕` として、まとめ行に入れる。
- 各表のいちばん右（根拠の左）には「コナンの把握」の列を置く。意味と、行の選び方（個別の行とまとめ行・並び順）は `knowledge-matrix/README.md` を見る。
- 自明でないセルには脚注を付ける。脚注 ID は `[^K<表番号>-<人物ID の C- を除いた部分>]`（例：`[^K1-mori-ran]`）。1 人につき 1 表で 1 つの脚注にまとめ、列ごとの根拠はその中に書く。同じ根拠を複数人で共有するときは、内容がわかる名前の脚注を共有してよい（例：`[^K6-doki]`）。

## 7. 人名の書き方

- 同じ姓の人物がいる場合は、姓だけで書かない。特に諸伏兄弟は「景光」「高明」または「諸伏景光」「諸伏高明」と書く（「諸伏」だけでは高明と混同する）。
- 同様に、横溝兄弟（参悟・重悟）、萩原姉弟（千速・研二）、工藤家、毛利家、赤井家、宮野家、黒羽家、本堂家、服部家、遠山家、鈴木家も、区別が必要な文脈では下の名前を付ける。

## 8. ネタバレの扱い

- `characters.md`・`knowledge-matrix/`・`profiles/` は答えを含む（正体・所属・生死・素性・過去）。ネタバレを避けたい人に見せるときは、research スキルが既読範囲に合わせて伏せる。
- `foreshadowing/README.md` の一覧表と `open-questions.md` のタイトルはネタバレなしで読めるように書く（5. を参照）。

## 9. relationships/ の記入規則

`data/relationships/` 以下には、恋愛関係（`loves.md`）、グループ・組織（`groups.md`）、家族・きょうだい（`families.md`）、友人・ライバル関係（`friends-and-rivals.md`）を記録する。どのファイルに書くかと各項目の書き方は `relationships/README.md` を見る。
知識表（`knowledge-matrix/`）の記号とは **別系統** の記法を使う。タイトルはネタバレを含んでよい（現状記録のため）。

### 9.1 恋愛関係の段階（loves.md）

男女の恋愛関係（いわゆるノマカプ）のみを対象とする。

| 段階 | 定義 |
|---|---|
| `A` | 交際中・恋人関係が成立 |
| `B` | 相思相愛だが交際は未成立・未確定 |
| `C` | 既婚・夫婦 |
| `D` | 過去の恋人・死別など |
| `E` | 現状片思い（一方のみ恋愛感情あり） |

- 原作漫画を基準とし、劇場版・アニオリ等の描写には `[劇場版]` 等のタグを付けて補足する。
- ファンカップリングや根拠の弱い推測は収録しない。

### 9.2 グループ状態（groups.md）

| 記号 | 意味 |
|---|---|
| `◎` | 活動中 |
| `△` | 一部のみ活動中・休止中 |
| `✕` | 解散・消滅 |
| `?` | 不明・要確認 |

### 9.3 ID 規則（relationships/）

| 種類 | 形式 | 例 |
|---|---|---|
| グループ・家族 | `G-<英字略称>` | `G-shonen-tantei`、`G-keisatsu-gakko`、`G-kudo-family` |

カップル・友人ペアは人物 ID（例：C-kudo-shinichi × C-mori-ran）の組み合わせで表す。独立した ID は振らない。

## 10. profiles/ の記入規則

`data/profiles/` には、作品がその人物をどこまで描いたか（私生活・過去・内面・素性）を、人物を行にした表で記録する。記号の意味、過去の区分（幼少期〜中学／就職前／就職後）、行の選び方は `profiles/README.md` を見る。
記号は知識表と同じもの（6. の `◎`・`〇`・`△`・`✕`・`ー`・`?` と `†`）を使うが、意味は「その人物がどこまで描かれているか」になる。セルの記号は程度だけを表し、中身と根拠は脚注に書く。行の選び方（グループ・並び順・まとめ行）も知識表と同じで、`lint_data.py` が同じ規則で見る。
