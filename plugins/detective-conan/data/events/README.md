# 出来事の正本

> **ネタバレ注意**：正体・生死・素性・過去など、答えを含む。

作中で起きた出来事に ID を振り、1 か所にまとめる。知識表・人物の掘り下げの脚注、relationships の経緯、伏線などは、根拠の場面をこの ID で参照する。単位・ID・参照の決まりは `conventions.md` の 11. にある。

## ファイル

| ファイル | 区分 | ID の形 | グループ（`##`）の見出し |
|---|---|---|---|
| `01-manga/<巻>.md`（1 巻 1 ファイル。例：[01-manga/104.md](01-manga/104.md)） | `[原作]` | `E-<database の事件の先頭 File>-NN` | `## File 1106–1109（104巻「…」）` のあとに `` `E-1106` `` |
| `01-manga/unpublished.md` | `[原作]`（database に無い話） | `E-<その File>-NN` | `## File 1167「迷い込んだ蘭」（単行本未収録／サンデー 2026 年 42・43 合併号）` のあとに `` `E-1167` `` |
| `02-movies/<作>.md`（1 作 1 ファイル。例：`02-movies/26.md`） | `[劇場版]` | `E-M<作品の番号>-NN` | `## 劇場版第 26 作『黒鉄の魚影』` のあとに `` `E-M26` `` |
| `02-movies/<略号>.md`（番号の無い番外編。例：`02-movies/MLV.md`） | `[劇場版]` | `E-M<略号>-NN` | `## 劇場版『ルパン三世VS名探偵コナン THE MOVIE』` のあとに `` `E-MLV` `` |
| [03-anime-original.md](03-anime-original.md) | `[アニオリ]`・`[TVSP]` | `E-A<最初の話数>-NN`、TVSP・OVA は `E-A<略号>-NN` | `## アニメ第 965–968 話「…」` のあとに `` `E-A965` `` |
| [04-magic-kaito.md](04-magic-kaito.md) | `[まじっく快斗]` | `E-XMK<巻>-NN` | `## まじっく快斗 1巻` のあとに `` `E-XMK1` `` |
| [05-other.md](05-other.md) | `[スピンオフ]` | `E-X<略号>-NN` | `## 『警察学校編 Wild Police Story』` のあとに `` `E-XWPS` `` |

- 原作は単行本 1 巻 1 ファイル（巻の番号を 3 桁にする。`001.md`…`110.md`）、劇場版は 1 作 1 ファイル（作品の番号を 2 桁にする。`01.md`…`29.md`。番外編は略号）に分ける。ファイルは件ができたときに作る（空のファイルは置かない）。
- 原作の件は、グループ（事件）の見出しにある最初の巻で、ファイルが決まる（例：`File 1106–1109（104巻「…」）` は `01-manga/104.md`、`File 1047–1050（98・99巻「…」）` は `01-manga/098.md`）。
- database に無い話（単行本未収録）は、巻が決まっていないので `01-manga/unpublished.md` に書く。database に入ったら、グループの見出しを事件の形に直して、巻のファイルへ移す（件の ID は変えない）。
- グループの見出しの最後には、そのグループの ID の頭（`E-` から連番の前まで）をインラインコードで書く。
- 原作のグループは database の事件にする。見出しは `conventions.md` の 3.1 の形で、事件の File の範囲を `python scripts/conan_db.py case <事件名>` で引いて書く。database に無い話は、1 話ずつのグループにする（`## File 1167「迷い込んだ蘭」（単行本未収録／サンデー 2026 年 42・43 合併号）` のあとに `` `E-1167` ``）。
- グループは話の順（原作は File の順、劇場版は作品の番号の順）に並べる。グループの中の件も話の順に並べる。連番は登録した順なので、番号が前後することがある。
- 原作のグループの見出しが変わっても（database に無かった話が事件に入ったときなど）、件の ID は変えない。`lint_data.py` は、原作の件の ID の数字が、グループの File の範囲に入っているかと、グループがその巻・作品のファイルにあるかを見る。

## 1 件の書き方

```markdown
### E-<グループ>-NN <何が起きたか>

- 区分: [原作]
- 出典: 原作 File <番号>「<話タイトル>」（<巻>巻「<事件名>」）
- 時期: 物語の今
- 場面にいた人物: <名前> `C-…`、<名前> `C-…`（電話）
- 出来事:
  - <写し元から写した文>
    - 知識:
      - <K の ID か文>
        - <名前> `C-…`（<知り方>）
        - <名前> `C-…`（<知り方>）
    - 関係:
      - <名前> `C-…` × <名前> `C-…` — <どういう関係になったか>
  - <写し元から写した文>
- 関わる ID: Q-…
- 要確認: <確かめられなかったこと>
- 写し元（<コミット>）: <data からのパス> `[^<脚注 ID>]`、<data からのパス>「<見出し>」
```

欄はこの順に書く。書く欄が無いときは、その行ごと省く（必須の欄は省かない）。

| 欄 | 必須 | 書くこと |
|---|---|---|
| 見出し | ○ | `### <ID> <何が起きたか>`。主語と相手がわかる 1 文にする。人名は `conventions.md` の 7. に従う（赤井家なら「赤井秀一」）。答えを書いてよい。写し元に無い事実は入れない |
| 区分 | ○ | 正史区分タグを 1 つ。ファイルごとに決まっている（上の「ファイル」の表） |
| 出典 | ○ | 原作は `conventions.md` の 3.1 の File 表記（1 話なら話タイトルつき）。場面が 2 話にまたがるときと、写し元が範囲でしか書いていないときは範囲で書き、どの話かを「要確認」に入れる。アニメの話数は、確かめられたときだけ `／アニメ第 N 話` と添える。劇場版・アニオリなどは `conventions.md` の 3. の書き方 |
| 時期 | ○ | その場面がいつのものか。`物語の今`、または `過去：<作中の言い方>`（例：`過去：「17年前」`）。言い方が出ていなければ `過去：要確認`。西暦に直さない |
| 場面にいた人物 | | その場面に描かれていると確かめた人物だけを、名前と人物 ID で「、」でつなぐ。補足（電話・盗聴・回想など）は括弧で添える。その回に出ているだけでは入れない。ほかにもいたかを確かめていなければ、最後に「（ほかは要確認）」と書く |
| 出来事 | ○ | 下の「出来事の書き方」 |
| 関わる ID | | 「出来事」のラベルの下に書けない ID（考察の `Q-` など） |
| 要確認 | | 確かめられなかったこと。写し元どうしの食い違いは、どちらにも寄せずに両方を写し、ここに書く |
| 写し元 | ○ | 下の「写し元の書き方」 |

人名は `characters.md` の人物カードの名前で書き、後ろに人物 ID を付ける（知識表の行と同じ）。

### 出来事の書き方

- 1 段目（2 字下げの `-`）：何が起きたか。1 項目に 1 つの出来事を書く。文は写し元から写す（下の「確かめ方」）。
- 2 段目（4 字下げの `-`）：その出来事で何が変わったかの種類。`- 知識:` のように、次の 5 つのラベルだけを書く。1 つの出来事に同じラベルは 1 回だけ書き、同じ種類の項目はその下にまとめる。
- 3 段目（6 字下げの `-`）：ラベルの中身。1 行に 1 つ書く。
- 4 段目（8 字下げの `-`）：「知識」だけに使う。3 段目に「何を知ったか」を書き、4 段目に「誰が知ったか」を 1 人 1 行で書く。同じことを何人かが知ったら、同じ 3 段目の下に並べる。
- ラベルの下には、写し元がその出来事を根拠にしていると書いているもの（知識表の脚注の「K4-2 は…による」、relationships の経緯に挙がっている場面など）だけを書く。自分の読みで足さない。
- ラベルが無い出来事もある。

| ラベル | 3 段目（と 4 段目）の書き方 | 根拠にする写し元 |
|---|---|---|
| `知識` | 作中の人物が知ったこと（前から知っていたことが、この場面でわかったときも含む）。3 段目は、知識表の列の中身そのものを知ったときは K の ID だけ（例：`K4-2`）、一部だけ・どの列にも当たらないときは文で書いて関わる K を添える（例：`浩司の父が…こと（K4-1 の一部）`）。4 段目は ``<名前> `C-…`（<知り方>）`` | 知識表の脚注 |
| `関係` | 人物どうしの関係が変わったこと。``<名前> `C-…` × <名前> `C-…` — <どういう関係になったか>``。`loves.md` の段階が変わったら段階も添える（例：`段階 E → B`）。グループに入る・抜けるときは ``<名前> `C-…` — G-… に入る`` | relationships の経緯 |
| `伏線` | 伏線の初出・経過・回収に当たること。`F-… — <初出・経過・回収>` | 伏線の初出・経過・回収の欄 |
| `描写` | 読者に示されたこと（人物の掘り下げの列に当たること）。``<名前> `C-…` — <P の ID か文>`` | 人物の掘り下げの脚注 |
| `生死` | ``<名前> `C-…` — 死亡`` または ``<名前> `C-…` — 死んだように見せかける`` | 死を書いている写し元 |

```markdown
  - <1 段目：何が起きたか>
    - 知識:
      - K4-2
        - 工藤新一 `C-kudo-shinichi`（推理した）
        - 赤井秀一 `C-akai-shuichi`（推理した）
    - 伏線:
      - F-RUM-008 — 回収
```

「知識」の 4 段目の知り方は、次のどれかにする。補足を書くときは、知り方の前に「。」で区切って書く（例：`（コナンの推理に同意。推理した）`）。どの記号（◎・〇・△）にするかは知識表の側で決め、正本には知り方だけを書く。

| 知り方 | 意味 |
|---|---|
| `見た` | その場面で、自分の目で見た |
| `聞いた` | その場面で、人から聞いた（本人が明かした・電話・盗聴を含む） |
| `推理した` | 自分で推理してたどり着いた（人の推理に同意したときも含む） |
| `疑った` | 疑った・違和感を持った |
| `既知` | この場面より前から知っていて、この場面の言動（話した・ほのめかした など）でそれがわかる。いつ知ったかは、知った場面の件に書く |

- 「知識」は作中の人物が知ること、「描写」は読者に示されることで、別のものとして書く（例：回想の字幕で人物の所属が出る場面は、作中の誰も知らないので「描写」だけ）。
- その場にいたが、聞いた・見たかがわからない人物は、「場面にいた人物」には入れ、「知識」には入れない。この差が、知識表の `△`（場面にいたが、聞いた・見たかがわからない）の材料になる。
- ほかの種類（所属の変化など）が要るようになったら、この表に足してから使う。

### 写し元の書き方

```markdown
- 写し元（b2989ad）: knowledge-matrix/04-haneda-case.md `[^K4-kudo-shinichi]`、relationships/friends-and-rivals.md「羽田浩司 × 浅香（若狭留美）」
```

- 括弧の中には、写したときのリポジトリのコミット（短い形）を書く。写し元の文は、あとで ID に置き換えるとファイルから消えるので、コミットを書いておけば `git show <コミット>:plugins/detective-conan/data/<パス>` で読み直せる。
- コミットは、作業しているブランチを作った main のコミット（`git rev-parse --short $(git merge-base HEAD origin/main)`）を書く。ブランチの途中のコミットは、rebase や衝突の解消で hash が変わると読めなくなるので書かない。写し元を同じブランチで直してから写すことはしない（直しは別のブランチで行い、main に入ってから写す）。PR はマージコミットでマージする（squash すると、ブランチのコミットが main から読めなくなる）。
- 写し元の行は、コミットごとに 1 行にして、2 行以上書いてよい。あるファイルの PR で作った件に、あとで別のファイルの PR で写した文を足すときは、前の写し元の文はもう ID に置き換わって消えているので、前の行は変えずに、そのときのコミットで行を足す。同じコミットの写し元は 1 行にまとめる。

```markdown
- 写し元（<前の PR のブランチを作った main のコミット>）: knowledge-matrix/04-haneda-case.md `[^K4-kudo-shinichi]`、foreshadowing/02-rum.md「F-RUM-008」
- 写し元（<あとの PR のブランチを作った main のコミット>）: knowledge-matrix/03-akai-family.md `[^K3-kudo-shinichi]`
```

- 場所は、`data/` からのパスに続けて、脚注ならインラインコードで `` `[^脚注 ID]` ``、見出しの節なら「見出しの文字列」で書く。行番号は変わるので使わない。
- database のあらすじから写したときは `database/dataset_csv/Number-Title-Explain.csv「<事件名>」` と書く（database は submodule の今の中身を読む）。
- `data/` にも database にも無いことを、原作・日本語の出典で確かめて足したときは、写した文の中に出典を括弧で書く（下の「確かめ方」の 5）。

## ほかのファイルから参照するとき

- ID だけを書く（リンクにしない。File 表記は並べない）。例：「K4-2 は E-1106-01 による。」
- `lint_data.py` は、参照している ID が実在するかを見る。
- 2026-10 の時点では、ほかのファイルはまだ File 表記で根拠を書いている。ID への置き換えは、写し元のファイルごとに分けて進める（下の「根拠を ID に置き換えるとき」）。

### 根拠を ID に置き換えるとき

知識表・人物の掘り下げの脚注を、出来事の ID で書き直すときの決まり。relationships の経緯と「根拠」の行の書き方は、relationships の置き換えを始める前に決める。

- 場面の説明（File 表記、台詞、誰が何をしたか）と、その場面についての要確認（台詞の文言など）は、正本の件に移し、脚注には残さない。
- 脚注に残すのは、記号を決めた理由（推理の段階なので `〇`、伝わる経路、例外など）と、そのセルだけの要確認。理由に場面の中身が要るときは、短くして残す。
  - 例：「E-1110-01 でも、優作が有希子に、この見立てに新一も同意していると話している。推理の結論で、若狭本人が認めるなど確かめる描写はないので `〇`。」
- その場にいたが、聞いた・見たかがわからない（知識表の `△`）ときは、その場面の件を ID で示す（件の「場面にいた人物」にいて、「知識」にはいない）。
  - 例：「K4-1 は、E-948-05 の場にいたが、ジョディが資料を見たかは描かれていないので `△`。」
- 「話す場面はない」「関わる場面はない」のように、場面が無いことは文のまま書く。その文の中で根拠にしている場面は ID にする。
- 「File 1106–1109（104巻「17年前の真相［遠見の角行／女王の謀（クイーンズ・ギャンビット）］」）に出ているが、知る場面はない」のように、話の範囲について言うことは、File 表記のまま書く。
- 置き換えるファイルの PR では、そのファイルの脚注が根拠にしている場面の件を作り（ほかのファイルの文も写してよい）、ID に置き換えるのはそのファイルだけにする。記号の誤りや写し元の誤りに気づいても、置き換えの PR では直さず、一覧にしてユーザーに伝える。
- 置き換えたら、消した文が件に写されているか（または脚注に残っているか）を `python scripts/check_event_copy.py --removed <ブランチを作った main のコミット> <data からのパス>` で確かめる（下の「写しを確かめるスクリプト」）。
- 脚注が根拠に挙げた件に、その行の人物の知識（人物の掘り下げでは描写）があるかも、`python scripts/check_event_copy.py --cited <data からのパス>` で確かめる（下の「写しを確かめるスクリプト」）。

置き換えが済んだファイル：`knowledge-matrix/04-haneda-case.md`（PR #33）、`knowledge-matrix/03-akai-family.md`（PR #34）、`knowledge-matrix/08-hondo-family.md`（PR #35。どの話かわからず件にしていない 3 場面は、今の書き方のまま）、`knowledge-matrix/01-conan-shinichi.md`（PR #36。話数がわからず件にしていない場面と、ユーザーが件にしないと決めたアニメの話は、今の書き方のまま）。

## 書くときの確かめ方

正本はほかのファイルの根拠になるので、1 件でも間違いが入るとあちこちに広がる。記憶や推測では書かず、次の手順で少しずつ書く。

1. **書き写しから始める。** 出来事の中身は、今のデータ（知識表・人物の掘り下げの脚注、relationships の経緯、`profiles/timeline.md`）にある文をそのままコピーしてから整える。自分の記憶や Web の要約をもとに新しく書かない。
2. **写し元を記録する。** 各件の「写し元」に、どのファイルのどの脚注・項目から写したかを書く（脚注 ID や見出しで書く。行番号は変わるので使わない）。
3. **写したことを機械的に確かめる。** 写した文が写し元にそのまま含まれているかを、grep かスクリプトで確かめる。今のデータや database のあらすじから写した件は、`python scripts/check_event_copy.py <ID>` で確かめられる（下の「写しを確かめるスクリプト」）。整えたときに言い換えた部分は、写し元とどこが違うかを示す。
4. **話数を引き直す。** File 番号・話タイトル・事件名・巻は、写し元をそのまま信じず、`conan_db.py` で引き直す。写し元のほうが間違っていたら、正本には正しい値を書き、写し元の誤りは一覧にしてユーザーに伝える（写し元は、正本の作業とは別に直す）。
5. **写し元に無いことを足さない。** その場にいた人物、台詞の文言、作中の時期などを推測で埋めない。原作・database・日本語の出典で確かめられたものだけを、出典を付けて足す。確かめられなければ「要確認」と書くか、空けておく。とくに「場面にいた人物」は、その場面に描かれているかを確かめてから入れる（その回に出ているだけでは入れない）。
6. **食い違いはまとめない。** 同じ場面について写し元どうしで書き方が食い違っていたら、どちらかに寄せない。両方を写して「要確認」にし、ユーザーに伝える。
7. **少しずつ進める。** 1 回に書くのは 1 場面（または 1 つの話）分だけにする。書くたびにユーザーに見せ、確かめてもらってから次へ進む。
8. **Agent に調べさせたとき**は、結果をそのまま正本に入れない。写し元・database・原文と突き合わせてから入れる。
9. **台詞は日本語の出典で確かめ、英語のページから訳し戻さない。** WebFetch などの要約は細部を取り違えるので、話数と人物名は原文か database で確かめる。

新しい話の場面など、今のデータに写し元が無い件は、database のあらすじ・原文・`sources.md` の D の速報系 2 サイト以上で一致したものから書き、確かめた出典を写し元の欄に書く（`conventions.md` の 3.1・`sources.md`）。

## 写しを確かめるスクリプト

今のデータ（`data/` 以下）や database のあらすじから写した件を確かめるためのもの。おもに、今のデータの脚注・経緯から件を登録し直す作業（ほかのファイルの参照を ID に置き換える作業）で使う。git の履歴を読むので、ソースリポジトリでだけ動く。Web の出典から書いた件（新しい話など）は確かめられない。

```sh
python scripts/check_event_copy.py E-1106-01      # 1 件
python scripts/check_event_copy.py --all          # すべての件
python scripts/check_event_copy.py --removed a7cc331 knowledge-matrix/04-haneda-case.md   # 置き換えで消した文
python scripts/check_event_copy.py --cited knowledge-matrix/02-haibara-aptx.md   # 脚注が根拠に挙げた件の知識
```

- 「写し元」に書いたファイルを、その行のコミットの時点で読み、「出来事」の 1 段目と「要確認」の文が写し元にそのまま含まれているかを、「。」で区切った 1 文ずつ調べる。
- 含まれていない文は、写し元でいちばん近い文と、どこが違うか（`[-写し元にだけある部分-]`・`{+正本にだけある部分+}`）を表示する。言い換えたこと自体は誤りではないが、違いはユーザーに見せる。
- 「知識」「描写」「伏線」に書いた K・P・F の ID が写し元に出てくるかも調べる。「知識」「描写」は、まずその人物の脚注（`[^K4-akai-shuichi]` など）を探す。
- `--removed <コミット> <パス>…` は逆の向きを調べる。そのコミット（置き換える前）の時点と今のファイルを比べ、消えた行の文を 1 文ずつ、今の同じ場所（脚注なら同じ脚注、ほかの行は同じ見出しの節で書き換わった行）に残っているか、どれかの件（見出し・出典・「出来事」の 1 段目・要確認）にそのままあるか（一致）、近い文があるか（違いあり）、どちらでもないか（見つからない）で出す。行は場所ごとに比べるので、ほかの節に同じ行が残っていても、消した行は出る。見出しを変えた節の行は、すべて消えた行として出る。File 表記を「出典」へ移したことや、脚注の言い回しを変えたことも「違いあり」に出るので、目で確かめる。「見つからない」の文と、その扱いは PR の説明に書く。
- `--cited <パス>…` は、脚注 → 件の向きを調べる（git は使わず、今のファイルを読む）。知識表・人物の掘り下げの表の脚注で、その表の列 ID で始まる文（「K1-4・K1-5 は E-429-03 による」。範囲「K1-1〜K1-3」と列挙「K1-4・K1-5」を読む）に出てくる件に、その脚注の行の人物の知識（人物の掘り下げでは描写）があるかを見て、無いものを「無い」に出す。脚注を何行かで共有しているときと、1 行に何人もいるとき（少年探偵団など）は、全員を見る。パスを書かなければ、`knowledge-matrix/0*.md` と `profiles/0*.md` をすべて見る。
  - 見るのは、知識表では `◎`・`〇`、人物の掘り下げでは `◎`・`〇`・`△` のセル（`†` 付きを含む）だけ。知識表の `△`・`✕`・`?`・`ー` の理由に挙げた場面と、「コナンの把握」の列は見ない。
  - 「直した」を含む括弧（「（2026-10-28 に、10 年前の E-972-05 から…直した）」）の中の件は見ない。ほかの括弧（「（例：E-610-01）」など）の中の件は見る。
  - 2 列以上・2 件以上を 1 文で書いた理由は、どの列がどの件かがわからないので、どの件にもどれかの列の知識があるか、どの列もどれかの件にあるかだけを見る。
  - 「コナンの把握」の理由の文（「K1-3 は A：E-972-01 で…」のように、段階（A〜D・未確認）と「：」が続く文）から出たものは、「参考」の段に出す。知識は、その人がその場にいて、自分の言動で知っているとわかるときだけ書くので、コナンが気づく・思い出すだけの場面なら、知識が無くてよい。参考の段は終了コードに数えない。
  - 知識表では、件の「場面にいた人物」にいない人に「（場面にいた人物にもいない）」と添える。人の話から推した根拠（その場にいない人は「知識」に入れない）なら、知識が無くてよい。ただし、知識と一緒に「場面にいた人物」からも漏れていることがあるので、目で確かめる。
  - 列 ID で始まらない文（「工藤夫妻は E-49-01 の時点で事情を知っている」など）は見ない。
